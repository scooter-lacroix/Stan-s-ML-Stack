# REVIEW TASK — rusty-stack v0.3.0 tenet remediation

You are reviewing the **rusty-stack** codebase: a Rust ML-environment
installer/orchestrator for AMD ROCm GPUs. Crate root:
`<repo-root>/rusty-stack/src/`
(repo root: the top-level directory of this repository).

A remediation was just performed (v0.2.0 → v0.3.0) against the project
requirements ("tenets") below. Your job is to **verify, by reading the actual
source code, whether each tenet is genuinely met** — and to report violations
with concrete `file:line` evidence and severity.

---

## DIRECTIVE — REVIEW METHOD (READ CAREFULLY)

- **Inspect the actual source files.** Reading source code is the ONLY
  permissible review method. Open the files and read the implementations.
- **Tests are NOT permissible evidence.** Do NOT rely on `cargo test` output,
  test counts, or `#[cfg(test)]` modules to conclude a tenet is met. Do NOT
  write "tests pass, therefore correct."
- **Git history / diffs are NOT permissible evidence.** Do NOT cite commits,
  `git log`, `git diff`, or changelog claims as proof. Do NOT assume a listed
  CHANGELOG entry means the code does what it says.
- For every claim below, open the cited file(s) and confirm the behavior holds
  by reading the logic. If the code contradicts the claim, that is a finding.
- Report per-tenet: MET / PARTIALLY MET / NOT MET, with file:line evidence,
  the concrete gap, severity (Critical/High/Medium/Low), and what the source
  actually does. End with a short overall verdict.

## WHAT WAS CLAIMED COMPLETED (v0.3.0) — verify EACH against source, do NOT trust

**Substrate + single-source env (tenets 1 & 2 backbone)**
- New `core/registry.rs` — `InstalledComponentRegistry` persisted at
  `~/.mlstack/installed.json` (sealed-core, pip-package tracking).
- `platform/environment.rs` — `~/.mlstack/` consolidated root helpers
  (`mlstack_root/global/envs/cache/logs/triton`), deterministic Python
  resolution in `resolve_canonical_python_bin` (explicit override > managed
  global `~/.mlstack/global/bin/python` > discovery), `ensure_global_venv()`.
- `logging.rs` — `log_dir()` now uses canonical `mlstack_logs_dir()`.

**iGPU filtering (tenet 3)** — new canonical `gpu.rs`:
`INTEGRATED_PCI_DEVICE_IDS`, `INTEGRATED_GFX_ARCHS` (gfx1036/gfx1103),
`is_integrated_gpu_name` (case-insensitive), `is_integrated_by_pci_id`,
`device_is_integrated` (fail-safe). Claims: the 3 former divergent classifiers
now delegate to it; `installer.rs::parse_rocminfo_for_discrete_gpus` uses
`device_is_integrated` and no longer gates on `!name.is_empty()`;
`detect_gpu_list()` is the single entrypoint; `textgen.rs`/`comfyui.rs`
`detect_gpu_devices()` call it (no more hardcoded "0,1");
`migraphx_python.rs::build_rocm_env()` re-derives instead of trusting inherited
`HIP_VISIBLE_DEVICES`; `detect_gpu_count_sysfs` skips iGPU PCI ids;
`hardware.rs`/`platform/linux.rs` derive `gpu_count` from `detect_gpu_list()`.

**No-CUDA (tenet 4)** — new `installers/common/nvidia_blocklist.rs` (one unified
blocklist: nvidia-*/cuda*/cudnn/cublas/.../triton prefix/torch family/CUDA
wheel-URL markers, `filter_requirements`, `contaminated_packages`). Claims:
`installer.rs::filter_cuda_requirements` delegates; `megatron.rs::is_safe_package`
delegates; comfyui dispatch now filters requirements; CUDA env exports
(`TORCH_CUDA_ARCH_LIST`, `OMPI_MCA_opal_cuda_support`) stripped from the legacy
`.mlstack_env` writer (`installer.rs`), `permanent_env.rs`, and the bootstrap
emitter (`bootstrap/env_setup.rs` bash+fish).

**No-override (tenet 2)** — `deepspeed.rs::build_install_command` +
`build_force_reinstall_command` now use `--no-deps`.

**Functional verification (tenet 5)** — `component_status.rs::
pytorch_diagnostic_snippet` now exits non-zero when torch is not a ROCm build or
HIP unavailable (was unconditional `sys.exit(0)`).

**Uninstall/reinstall (tenet 6)** — new `uninstall.rs` (`uninstall_stack`,
cross-shell fish/bash/zsh sourcing-strip, cross-distro apt/dnf/pacman/zypper
ROCm purge, /opt/rocm wipe, env-file + registry removal); new
`rusty uninstall` / `rusty reinstall` subcommands in `src/bin/rusty.rs`.

**Logs/version (tenet 7)** — VERSION + Cargo.toml → 0.3.0; CHANGELOG [0.3.0].

The CHANGELOG itself lists some items as **deferred/scaffolded** (full
`--env <name>` named-env isolation; registry-driven sealed-core *gating* wired
into all dispatchers; textgen/comfyui functional probes; `VerifyRunner` wiring;
non-interactive `rusty install`). Confirm whether those deferrals constitute a
tenet gap or an acceptable partial.
