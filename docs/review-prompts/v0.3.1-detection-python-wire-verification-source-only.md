You are reviewing the **rusty-stack** codebase: a Rust ML-environment

The foundational requirement driving this work:

> The stack exists to make installing ROCm automated + easy. GPU detection
> MUST NOT depend on `rocminfo` (which only exists *after* ROCm is installed).
> Detection must work on a clean box with zero ROCm — correctly identify the
> AMD dGPUs, their gfx architectures, and correct enumeration for env vars —
> and everything else must derive from that single detection step. Separately,
> the managed Python must be one canonical env (≤3.13, prefer 3.12), all stack
> ops route through it, uv-first with a configurable backend, and it can be
> made the system default via a shell-aware opt-in.

## PART A — v0.3.1 install hotfix (post-merge bugs)

Verify each against source. These were surfaced by the first real install on
Arch (CachyOS); root-caused from `~/.mlstack/logs/rusty-stack.log`.

**A1. ROCm Arch install no longer triggers a full system upgrade.**
The Arch path previously emitted a bare `sudo yay` as its first command; `yay`
with no operation defaults to `yay -Syu` (a 419-package system upgrade as root)
which then aborted on an AUR cleanBuild menu (stdin closed → EOF). Confirm the
Arch ROCm install now builds a SINGLE user-space `yay -S --needed --noconfirm …`
command (yay must run as the user — makepkg refuses root), and that no code
path emits a bare `sudo yay`. Look in `installer.rs` (the `"rocm" =>` Arch
branch) and `installers/components/rocm.rs::pacman_install_commands`.

**A2. No-CUDA hard-prime intact.** Confirm the universal pip chokepoint in
`installer.rs::execute_native_command` still rejects any `nvidia-*`/`cuda*`
runtime package or CUDA wheel URL from any component, while permitting
torch/triton from the ROCm index.

**A3. Verification cannot rescue a failed install.** `installer.rs` previously
set `final_success = verification_outcome.success`, sealing a fully-aborted
ROCm install as "installed" because rocminfo still ran against a surviving
`/opt/rocm`. Confirm it is now `install_success && verification_outcome.success`
— verification may only make the verdict stricter, never rescue a failure.

**A4. Non-interactive privileged operations via askpass.** Confirm
`installers/common/askpass.rs` provides an RAII `SUDO_ASKPASS` helper (mode-0600
password file + mode-0700 `cat` script in a private temp dir, wiped on drop),
and that `uninstall.rs::run_privileged` uses `sudo -A` with it when a password
is supplied (falling back to `sudo -n` only when none). Confirm the uninstall
CLI (`src/main.rs`) threads a sudo password into `UninstallOptions` from exactly
three sources, in priority order: the `MLSTACK_SUDO_PASSWORD` env var, an
interactive TTY prompt, and the `--sudo-password` CLI flag.

**A5. pacman cascade purge + corrupted-dir cleanup.** Confirm
`uninstall.rs::build_system_purge_cmd` uses `pacman -Rcn` (cascade) so removing
`rocm-core` takes its whole dependent tree, and that
`clean_corrupted_pip_distributions` runs BEFORE pip and removes root-owned
`~`-prefixed pip leftovers via the askpass `sudo rm -rf` path (user-level
removal first, privileged fallback).

**A6. rpassword password capture.** Confirm `src/main.rs` (`sudo_creds` module)
reads the sudo password via `rpassword` (not a hand-rolled termios raw-read that
corrupted the capture).

**A7. Single binary.** Confirm the crate builds ONE `rusty-stack` binary (no
separate `rusty` `[[bin]]`); clap `name` and self-upgrade `expected_binary_name()`
are `rusty-stack`.

## PART B — rocminfo-free GPU detection (Track A)

New in `gpu.rs`. Verify against source + the box's `/sys/class/drm`.

**B1. Unified sysfs detector.** `gpu.rs::detect_amd_gpus()` walks
`/sys/class/drm/card*/device`, keeps vendor `0x1002`, and — CRITICAL — filters
on PCI **class** `0x030000` (VGA) / `0x030200` (3D). Confirm the class filter
exists and is correct: without it, AMD PCI bridges (`0x0604`) and HDMI audio
(`0x0403`) are miscounted as GPUs. Confirm it reads `device` (PCI device id),
`mem_info_vram_total`, classifies `is_integrated` via `device_is_integrated`,
and that **rocminfo is NOT consulted anywhere** in this function.

**B2. dGPU enumeration.** `detect_discrete_amd_gpus()` filters `!is_integrated`
and sorts by `pci_slot` (stable `HIP_VISIBLE_DEVICES` indexing). Confirm an iGPU
(e.g. Raphael `0x164e`) is excluded while every dGPU is kept.

**B3. PCI-ID → gfx matrix (RDNA2/3/4 parity).** `DISCRETE_PCI_ID_TO_GFX` must
cover RDNA2 (6x00), RDNA3 (7x00), RDNA4 (90x0) with equal completeness. Spot-check
against `/usr/share/hwdata/pci.ids`: `0x744c→gfx1100`, `0x747e→gfx1101`,
`0x7550→gfx1200`, `0x7590→gfx1201`, `0x73bf→gfx1030`, `0x73df→gfx1031`,
`0x73ff→gfx1032`, `0x743f→gfx1034`. Flag any wrong mapping or major gaps.

**B4. Arch resolution returns Option, never gfx000.** `pci_id_to_gfx` +
`gfx_from_marketing_name` (must include generic "Navi NN" patterns: Navi 48→gfx1200,
44→gfx1201, 31→gfx1100, 32→gfx1101, 33→gfx1102, 21→gfx1030, 22→gfx1031,
23→gfx1032, 24→gfx1034). Both return `Option`; unknown → `None`. Confirm the
string `"gfx000"` appears NOWHERE as a fallback in `gpu.rs` (grep the file).

**B5. Delegation + gfx000 eradication.** `installer.rs::detect_gpu_arch` returns
`Option<String>` and delegates to `gpu::detect_discrete_amd_gpus()`;
`detect_gpu_list` / `detect_discrete_gpus` delegate likewise. Grep ALL of
`src/` for `gfx000` — any remaining `gfx000` fallback is a Critical finding.

## PART C — Managed Python environment (Track B)

New in `platform/environment.rs` + `config.rs`. Verify against source.

**C1. Version cap (≤3.13, prefer 3.12, reject 3.14).** `resolve_managed_python`:
uv backend → `uv python find 3.12` first, else `uv python find ">=3.10,<3.14"`;
python backend → scans `python3.12, 3.11, 3.10, 3.13`. Confirm 3.14+ is
HARD-REJECTED (via `check_python_version_cap` parsing `--version`, rejecting
`major>3 || minor>13`), NOT merely deprioritized. Flag any path by which the
system Python 3.14 could be selected. (Known prior bug: the legacy
`discover_python_candidates` sorts versioned system Pythons newest-first, so
3.14 beats 3.12 — confirm the managed resolver does NOT inherit that.)

**C2. Global env creation.** `create_global_env` materializes exactly ONE env
at `~/.mlstack/global` (`uv venv ~/.mlstack/global --python <resolved>` for uv,
`<resolved> -m venv ~/.mlstack/global` for python), returning
`~/.mlstack/global/bin/python`. Confirm `resolve_canonical_python_bin` treats
this path as authoritative.

**C3. Backend toggle.** `config.rs` has a `python_backend` (`PythonBackend::Uv`
default when `uv` on PATH, else `Python`) with `MLSTACK_PYTHON_BACKEND` env
override and config.json persistence.

**C4. Shell-aware global prepend.** `offer_global_prepend` detects `$SHELL`
(bash/zsh/fish), prompts `[Y/n]` default-Y on TTY, acts on no-TTY/`yes_default`,
appends ONE idempotent line tagged `# mlstack-global-python` to the correct rc
(`~/.bashrc` / `~/.zshrc` / `~/.config/fish/config.fish`). Confirm idempotency
(marker-present → no-op) and that the rc is NOT modified when the user declines.

**C5. All stack ops route through the managed env.** Audit
`src/installers/components/*.rs` — flag any component that shells out to a bare
`python3` / `pip` for an INSTALL operation (not a launcher default, not a test).
The managed `python_bin` must drive installs.

## PART D — Wiring + zero-tolerance hygiene (Phase 2)

**D1. permanent-env arm fail-loud + de-sudo.** `installer.rs` `"permanent-env" =>`
calls `gpu::detect_discrete_amd_gpus()` directly, **bails** if empty ("no AMD
dGPU detected via sysfs") and **bails** if the primary dGPU's `gfx_arch` is
`None`. Confirm the old `sudo rocminfo` command execution is GONE from this arm
(it's read-only + broken under sudo's PATH). Confirm `HIP_VISIBLE_DEVICES` and
`PYTORCH_ROCM_DEVICE` derive from the same detector result, and `HSA_OVERRIDE`
uses the precise per-variant table (`GpuArchInfo::from_arch`, so gfx1101→11.0.1).

**D2. Managed Python wired into env creation.** The permanent-env arm calls
`resolve_managed_python` → `create_global_env` → `write_activate_snippets` →
`offer_global_prepend`, and the resolved `~/.mlstack/global/bin/python` is the
`python_bin` in `PermanentEnvConfig`.

**D3. Content-aware verification.** `component_status.rs::env_file_has_permanent`
must, after the marker check, parse `GPU_ARCH=` and return `false` for `gfx000`
or any arch not matching `gfx(9|10|11|12)…`. Confirm a broken env can no longer
be reported Verified.

**D4. No suppression.** Grep `src/` for `#[allow` attributed to this change-set.
`#[allow(dead_code)]` was added then removed during this work — confirm NONE of
`#[allow(dead_code)]` / `#[allow(clippy::…)]` were ADDED by the v0.3.1 work to
silence a fixable warning (pre-existing ones with a real justification are
acceptable; suppression of newly-introduced dead code is NOT). The dead
rocminfo/rocm-smi/lspci cascade parse fns should be DELETED, not suppressed.
